# Git 조회 인프로세스화와 동시 실행

작성: 2026-11-08. 구현·측정 반영: 2026-11-09.

여러 저장소를 동시에 검사하는 구조에 `gix` 조회를 연결했습니다. **같은 동시 실행 수의 Git 명령 방식과 비교한 macOS 결과는 [측정 보고서](macos-results-2026-11-09.md)에 있습니다.** 파일이 많은 구성에서는 macOS 할당기 잔류로 작업 후 메모리가 57~68MiB 남는 비용도 확인했습니다. Windows는 다른 기기에서 후속 검증합니다.

이 문서의 용어는 다음과 같습니다.

- **Git 명령 실행**: 설치된 `git` 실행 파일을 별도 프로세스로 실행합니다. Windows에서는 `git.exe`입니다.
- **라이브러리 내부 처리(인프로세스)**: 앱이 `gix`의 Rust 함수를 호출합니다. 해당 조회를 위한 Git 프로세스를 만들지 않습니다.
- **검사(Scan)**: 정리 가능한 항목을 찾습니다. **정리(Clean)**: 확인한 항목을 실제로 삭제합니다.

## 구현한 동작

개별 Scan과 Scan All은 같은 대기 목록과 동시 실행 상한을 사용합니다. CPU 수를 기준으로 기본 2~4개 저장소까지 실행하며, 먼저 끝난 저장소부터 결과를 갱신합니다. 같은 저장소의 중복 요청은 받지 않습니다. 취소하면 대기 요청은 버리고 실행 중인 검사를 회수합니다. 작업이 없을 때 남는 스레드나 polling은 없습니다.

Git 경로 설정이 Auto이면 로컬 조회에 `gix 0.90.0`을 사용합니다. Custom Git을 지정한 경우 설치별 설정을 보존하도록 조회도 지정한 Git으로 처리합니다. 조회 방식 선택은 [app/tasks.rs](../../src/app/tasks.rs), 작업 관리는 [app/scans.rs](../../src/app/scans.rs)와 [jobs/queue.rs](../../src/jobs/queue.rs)에 있습니다.

| 작업 | 구현 |
|---|---|
| 저장소 식별·기준 브랜치의 로컬 정보 | gix |
| 브랜치·ref·object 종류·병합 여부·조상 관계 | gix |
| 메인·연결·detached 워크트리와 잠금 상태 | gix |
| 스테이징·작업 파일·추적하지 않는 파일·서브모듈 상태 | gix. 전체 상태 iterator의 오류도 확인 |
| 정리·최신화 직전 재검사 | 새 gix 조회 상태로 다시 확인 |
| 삭제·워크트리 정보 정리·fetch·fast-forward | 기존 Git 명령과 guard |
| 허용된 원격 HEAD 질의 | 기존 Git 명령과 인증 경로 |

읽기 전용 [GitReadRepository](../../src/git/read.rs)가 앱 타입을 반환하며, [InProcessGitRunner](../../src/git/in_process.rs)가 조회 방식을 선택합니다. gix 결과를 Git 출력 문자열로 만들었다가 다시 파싱하지 않습니다. 저장소 객체·인덱스·그래프는 작업 중에만 보관합니다. gix 내부 병렬화는 끄고 저장소별 동시 실행만 적용했습니다.

## Git 명령으로 처리하는 경우

reftable, sparse checkout/index, 외부 필터 설정, fsmonitor, partial clone, 기존 grafts, 축약되거나 여러 개인 `branch.*.merge` 설정은 해당 저장소를 열 때 Git 명령 조회로 전환합니다. Custom Git 또는 `GIT_DIR` 지정도 Git 명령을 사용합니다. 권한·손상 오류를 기능 미지원으로 숨기지는 않습니다.

건강한 일반 저장소에서 로컬 원격 HEAD를 사용하는 Scan은 Git 실행 **0회**입니다. 같은 입력을 Git 명령으로 조회하면 저장소당 `6 + S`회이며, `S`는 파일 상태를 검사하는 연결된 워크트리 수입니다. 네트워크 질의·미지원 설정·실제 삭제 명령은 별도입니다. 실행 횟수 감소가 곧 같은 비율의 시간 단축을 뜻하지는 않습니다.

## 선택한 안과 남은 작업

기존 추천 A안인 **조회는 gix, 삭제·네트워크는 Git 명령**을 구현했습니다. [라이브러리 비교](alternatives.md)에는 선택 이유와 `git2` 대안, [전환 계획](migration-plan.md)에는 구현 범위와 후속 검증을 정리했습니다. [Windows 측정 계획](windows-benchmark.md)은 후속 작업입니다.

강제 삭제, 원격 브랜치 삭제, 자동 stash, 워크트리 폴더 직접 삭제, `.git` 파일 직접 수정은 계속 금지합니다. 기준 브랜치를 추측하거나 삭제 직전 재검사를 생략하지 않습니다. 허용 범위는 `PLAN.md` 18장·부록 A.12와 `AGENTS.md`에 반영했습니다. 라이브러리 삭제 API를 사용하는 C안은 구현하지 않았습니다.
